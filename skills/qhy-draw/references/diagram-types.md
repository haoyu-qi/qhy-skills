# qhy-draw 图型选择

选图型时先问自己：这张图最想回答的是“怎么走”“由什么组成”“谁和谁有关”“按什么顺序发生”还是“哪几个方案有什么差异”。

## 1. 流程图

适合：

- 有起点、终点、步骤和判断
- 需要讲“先后顺序”
- 有主路径和支线

不要用于：

- 主要是在讲组成关系，而不是步骤

布局重点：

- 主路径优先自上而下
- 判断节点尽量少
- 文本短，不在节点里塞说明书

## 2. 架构图

适合：

- 系统组成
- 模块职责
- 分层关系
- 服务、存储、接口之间的边界

核心：

- 层次
- 边界
- 主调用链

布局重点：

- 先分层，再摆节点，再连箭头
- 同层节点保持整齐，不要散点式漂浮

## 3. 数据流图

适合：

- 数据从哪里来，到哪里去
- 谁处理、谁存储、谁返回
- 重点在“流动”而不是“模块归属”

核心：

- 数据类型
- 数据方向
- 处理阶段

布局重点：

- 每条主箭头尽量标出数据类型
- 输入、处理、存储、输出分区清楚

## 4. 关系图

适合：

- 人、角色、对象、模块之间的连接
- 谁依赖谁、谁影响谁
- 多个实体之间的映射关系

核心：

- 连接逻辑
- 关系类型

布局重点：

- 节点分组优先
- 关系类型多时必须加图例

## 5. 时序图

适合：

- 讲参与方之间的调用顺序
- API 调用链
- Tool Call 执行过程

核心：

- 时间顺序
- 发起方和接收方
- 哪一步在等待、哪一步在处理

布局重点：

- 参与方横向排布
- 时间从上往下
- 超过 10 条消息时考虑拆图

## 6. 对比图

适合：

- 方案 A/B
- 旧方案和新方案
- 不同路径的取舍

核心：

- 维度一致
- 差异突出

布局重点：

- 列控制在 5 个以内
- 行尽量都是同一评价维度

## 7. 路线图 / 时间线

适合：

- 项目推进
- 阶段拆解
- 里程碑安排

核心：

- 时间轴
- 阶段划分
- 关键节点

## 8. 白板图 / 脑图

适合：

- 还在想、还在讨论、还没有严格定稿
- 需要保留探索感和发散感

核心：

- 把主线保住
- 允许局部不那么工整

注意：

- 白板感不等于混乱
- 仍要让人看得出中心和分支

## 9. Agent 架构图

适合：

- LLM、Planner、Tool、Memory、Observation 等协作关系
- RAG、Agentic Search、Tool Use、多 Agent 系统

核心：

- 控制层
- 工具层
- 记忆层
- 输出层

## 10. Memory 架构图

适合：

- Mem0、MemGPT、长期记忆、短期记忆
- 记忆写入、检索、整合、遗忘流程

核心：

- 读路径
- 写路径
- 存储分层
