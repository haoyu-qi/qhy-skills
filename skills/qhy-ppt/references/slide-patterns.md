# 页面类型速查

根据每一页的任务选页面，不要反过来先想视觉效果。

## 开场类

| 页面类型 | 适用场景 | 关键元素 |
|---|---|---|
| Cover | 封面 | kicker、主标题、副标题、作者/日期 |
| TOC | 目录 | 3 到 6 个章节，不要过细 |
| Section Divider | 章节转场 | 大编号、章节名、一句过渡 |

## 解释类

| 页面类型 | 适用场景 | 关键元素 |
|---|---|---|
| Bullets | 要点解释 | 3 到 5 条，不要写成长段 |
| Two Column | 概念 + 示例 | 左右职责明确，不平均切块 |
| Three Column | 三个并列维度 | 只在真的三分法成立时使用 |
| Big Quote | 金句、结论、价值主张 | 一句主文案 + 轻量补充 |

## 数据类

| 页面类型 | 适用场景 | 关键元素 |
|---|---|---|
| Stat Highlight | 一个核心数字 | 数字、单位、解释句 |
| KPI Grid | 多指标概览 | 4 到 6 项指标，含趋势 |
| Table | 列表对比 | 行数要控，读者要扫得动 |
| Comparison | Before / After | 差异点明确，一眼能懂 |
| Pros / Cons | 取舍分析 | 两边数量不要失衡太大 |

## 结构与流程类

| 页面类型 | 适用场景 | 关键元素 |
|---|---|---|
| Timeline | 时间线 | 节点不超过 6 个 |
| Roadmap | 现在 / 接下来 / 之后 | 适合计划与路线图 |
| Process Steps | 操作步骤 | 4 到 6 步最稳 |
| Flow Diagram | 系统流转 | 箭头、输入输出、关键节点 |
| Architecture Diagram | 架构说明 | 分层、边界、职责 |
| Mindmap | 主题发散 | 中心概念 + 分支 |

## 演示类

| 页面类型 | 适用场景 | 关键元素 |
|---|---|---|
| Code | 技术实现 | 只保留重点代码片段 |
| Diff | 修改前后 | 用于重构、优化、对比 |
| Terminal | CLI / Agent / 命令流 | 命令、输出、解释 |
| Image Hero | 强视觉图页 | 一张主视觉 + 一句结论 |

## 收尾类

| 页面类型 | 适用场景 | 关键元素 |
|---|---|---|
| CTA | 行动建议 | 下一步、联系人、链接 |
| Thanks | 结束页 | 标题、联系方式、Q&A |

## 选择规则

- 一页只能有一个主动作
- 需要结论时先上 `Stat Highlight` 或 `Big Quote`
- 需要解释时用 `Bullets` 或 `Two Column`
- 需要结构时用 `Flow Diagram` 或 `Architecture Diagram`
- 需要计划时用 `Timeline` 或 `Roadmap`
