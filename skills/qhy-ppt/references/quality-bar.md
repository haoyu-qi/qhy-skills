# qhy-ppt 质量底线

这是所有 deck 共用的质量底线。开始写页之前必须先对齐。

## 1. 先有叙事，后有页面

- 演示文稿不是卡片拼盘
- 每一页都要承担一个明确动作：引入、解释、证明、对比、决策、收尾
- 同一页里不要同时承担“背景 + 细节 + 结论 + next step”

## 2. 抗模板味

- 不要默认封面居中大字后一路三栏卡片到底
- 不要每一页都同样密度、同样留白、同样节奏
- 不要为了“像 PPT”而堆渐变、玻璃拟态、发光边框
- 技术分享优先清晰可信，商业 pitch 优先说服力，课程优先可跟随性

## 3. 页面密度

| 密度 | 适用页面 | 处理方式 |
|---|---|---|
| 稀 | 封面、章节页、结尾页 | 一个主锚点即可，留白要大 |
| 中 | 大多数正文页 | 2 到 4 个内容区块，主次分明 |
| 密 | 数据、对比、路线图 | 用分组、编号、线条和对齐解决，不要把所有信息塞进小卡片 |

## 4. 内容纪律

- 标题要能独立成立，不要写成空泛口号
- 数据要具体，避免“100x”“颠覆式”“全面升级”这类伪强势表达
- 技术页优先事实、结构、取舍；不要用营销文案替代解释
- 商业页优先结论、证据、商业含义；不要把过程细节压过结果

## 5. HTML 现实约束

- 默认单文件 HTML，内联 CSS 与必要 JS
- 不依赖外部图片、外部字体、外部图标库
- 优先用 CSS、SVG、几何形状和纯文本构图
- 允许少量脚本实现翻页和进度，但不要引入复杂运行时

## 6. 最终检查

- [ ] 封面是否建立了明确预期
- [ ] 正文是否按“问题 -> 解释 -> 证据 -> 行动”推进
- [ ] 页面之间是否有节奏变化
- [ ] 有没有任何一页需要用户停下来猜“这一页想表达什么”
- [ ] 是否仍然适合离线打开和继续手改
