# qhy-draw 提示配方

这些配方不是给用户看的固定模板，而是为了帮助模型在常见图型里稳定输出高质量结构。

## 1. 架构图配方

使用条件：

- 用户想讲系统组成、服务边界、层级关系

内部提示骨架：

- 明确图要回答的系统问题
- 划分 3 到 5 个层级
- 每层保留代表性节点
- 连接主调用链和关键依赖
- 必要时补图例

## 2. 数据流图配方

使用条件：

- 用户重点在“数据从哪里来，到哪里去，被谁处理”

内部提示骨架：

- 列出输入、处理、存储、输出
- 每条箭头写清数据类型
- 主数据流用最强视觉权重
- 控制流和事件流降权

## 3. 流程图配方

使用条件：

- 用户重点在步骤顺序、判断和执行链路

内部提示骨架：

- 找起点、终点、关键判断
- 决策节点尽量少而明确
- 主路径自上而下
- 分支不要超过 3 层

## 4. 时序图配方

使用条件：

- 用户重点在参与方之间的调用先后

内部提示骨架：

- 先列参与方
- 再列消息顺序
- 激活期只标关键过程
- 超过 10 条消息时考虑拆场景

## 5. Agent / Memory 图配方

使用条件：

- 用户描述 LLM、Planner、Tool、Memory、RAG、Mem0 等系统

内部提示骨架：

- 先判断是 Agent 架构图还是 Memory 架构图
- 优先抽取核心层次
- 读写链路用不同箭头
- 输出图例说明箭头语义

## 6. 对比图配方

使用条件：

- 用户在比较两个或多个方案

内部提示骨架：

- 先统一对比维度
- 列不超过 5 列
- 行不超过 8 行
- 差异比完整性更重要

## 7. 拆图配方

使用条件：

- 一张图承载不了所有逻辑

内部提示骨架：

- 先确定主图回答什么
- 子图各回答一个补充问题
- 保证主图脱离子图也能独立成立
