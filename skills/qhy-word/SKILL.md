# qhy-word

一个面向中文正式文档写作与整理的技能。它关心的是文档是否能被人顺畅阅读、快速定位重点并进入后续审批、协作或执行，而不是只把材料“写长一点”。

## 核心原则

1. 先确定文档用途，再确定语气和结构。
2. 文档首先要可读，其次才是完整。
3. 标题体系必须稳定，层级不能乱跳。
4. 内容要像在推动事情，而不是像在堆字数。

## 执行顺序

生成前按顺序读取：

1. `references/document-modes.md`
2. `references/writing-standards.md`
3. `references/review-checklist.md`

## 先判断三件事

- 文档用途：汇报、申请、说明、方案、纪要、制度、复盘
- 读者对象：领导、客户、同事、外部合作方、执行团队
- 当前状态：只有要点 / 已有草稿 / 需要重写 / 需要润色

## 常见文档模式

| 模式 | 适用内容 | 重点 |
|------|----------|------|
| 方案文 | 项目方案、运营方案、合作方案 | 目标、路径、资源、收益 |
| 报告文 | 调研、总结、阶段汇报、复盘 | 结论、证据、问题、建议 |
| 说明文 | 流程说明、产品说明、制度说明 | 定义清楚、边界清楚、步骤清楚 |
| 纪要文 | 会议纪要、访谈纪要、同步记录 | 结论、任务、责任、时间点 |

未指定时，默认按“方案文”处理。

## 输出规范

### 默认输出

优先输出：

1. 文档标题
2. 一级结构
3. 完整正文或重点章节正文

### 当材料还很散时

先输出：

- 文档目的
- 推荐结构
- 还缺哪些信息

## 必须做到

- 先让读者知道文档为什么存在
- 标题和段落都能独立表达含义
- 结论、问题、建议、行动分开写
- 纪要类文档必须落到人和动作

## 禁止做到

- 禁止空泛开头铺陈半天还没进入主题
- 禁止段落层级混乱
- 禁止把口语转录原样塞进正式文档
- 禁止用“赋能、闭环、抓手”之类空词撑场面

## 输出前自检

- [ ] 文档用途是否明确
- [ ] 标题层级是否稳定
- [ ] 有没有把结论藏在中后段
- [ ] 读者是否能快速找到重点
- [ ] 文档是否真的可提交、可审阅、可继续协作
