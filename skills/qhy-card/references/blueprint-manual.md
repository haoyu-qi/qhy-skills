# 蓝图技术手册风

适用于设备配置、部署教程、软件安装、操作手册、接口参数说明和故障排查。

## 定位

将操作文档压缩成一张可扫描、可执行、可验收的 HTML 卡片。画面应像工程师的现场速查表：准确、克制、层级清晰，同时保留足够的传播感。

## 与蓝图波普风的区别

| 判断项 | 蓝图技术手册风 | 蓝图波普风 |
|---|---|---|
| 核心任务 | 完成配置或操作 | 理解、比较或选购 |
| 主要内容 | 步骤、参数、状态、检查 | 知识点、数据、对比、避坑 |
| 主锚点 | 最关键的操作顺序 | 最重要的结论或数据 |
| 视觉语气 | 工程手册、终端面板、验收单 | 实验手册、波普标记、信息拼贴 |
| 推荐模板 | `assets/blueprint_manual_template.html` | `assets/infograph_template.html` |

## 内容结构

优先采用以下顺序，并按材料实际内容增删：

1. **标题区**：教程名称、适用对象、文档编号或版本。
2. **状态模拟区**：用终端、设备读数、接口状态或简化 UI 作为技术氛围锚点。
3. **使用前准备**：列出依赖、权限、连接和输入信息。
4. **关键步骤链**：突出最容易做错、顺序不能颠倒的操作。
5. **参数地图**：用编号、字段名、填写规则、示例值组成可扫描表格。
6. **现场备注**：解释端口确认、账号组成、单位换算等局部问题。
7. **保存与验收**：分别列出执行步骤和成功表现。
8. **风险提示**：区分示例值与生产值，指出不可随意修改的字段。

## 主锚点规则

- 从原始内容中找出一个会决定操作成败的顺序或动作。
- 用高对比深色块、警示签或加粗箭头突出它。
- 不要让普通步骤和关键步骤同权。
- 如果没有严格顺序，改用“参数填写规则”或“成功判定”作为主锚点。

## 布局规则

- 默认画布宽度为 1200–1280px，适合生成纵向长图。
- 标题区使用约 `60/40` 的非对称双栏：左侧标题，右侧设备读数或终端模拟。
- 准备区可使用大数字与检查清单形成轻重对比。
- 关键步骤链最多同时展示 3–5 个节点；节点多时改为纵向路径。
- 参数区使用“编号 + 字段 + 说明”的表格结构，不要把每个参数做成独立卡片。
- 现场备注作为窄侧栏，不与参数表平均分栏。
- 验收区使用深色执行面板和浅色成功检查面板。

## 视觉语言

### 推荐色板

```css
:root {
  --paper: #f2f6f7;
  --ink: #182d35;
  --muted: #5d727a;
  --blue: #287fa1;
  --blue-soft: #d9eef5;
  --teal: #0a8f85;
  --teal-soft: #d6efeb;
  --yellow: #ffe56f;
  --orange: #f29b38;
  --pink: #d94d72;
  --white: #fffefa;
}
```

- `--ink` 用于标题、关键步骤和终端面板。
- `--blue` 用于坐标标签、结构线和准备区。
- `--teal` 用于通过状态、检查项和成功反馈。
- `--yellow` 只标记主锚点，不要大面积铺满。
- `--orange` 用于操作箭头和注意事项。
- `--pink` 只用于高风险提示或关键顺序标签。

### 字体

- 中文正文使用系统无衬线字体栈。
- 标题可使用宋体与无衬线混排，但必须保证粗细对比。
- 端口、IP、编号、版本和原始报文使用等宽字体。

### 背景

使用 CSS 网格营造蓝图纸感，不使用远程图片：

```css
background-color: #f2f6f7;
background-image:
  linear-gradient(rgba(40,127,161,.09) 1px, transparent 1px),
  linear-gradient(90deg, rgba(40,127,161,.09) 1px, transparent 1px),
  linear-gradient(rgba(40,127,161,.035) 1px, transparent 1px),
  linear-gradient(90deg, rgba(40,127,161,.035) 1px, transparent 1px);
background-size: 40px 40px, 40px 40px, 8px 8px, 8px 8px;
```

## 文案规则

- 使用界面中的真实字段名，不自行改写产品术语。
- 写清单位、默认值、填写规则和数据来源。
- 示例统一使用“如”或“示例”，不得让示例值看起来像通用生产配置。
- 可选参数明确标注“可省略”或“选填”。
- 需要咨询其他角色时，写明具体角色，如“咨询硬件产品经理”。
- 验收标准要可观察，例如“按钮置灰”“报文持续刷新”“数量大于0”。
- 删除“确保顺利完成”“赋能高效使用”等空话。

## 移动端

- `900px` 以下将标题、参数区和验收区改为单列。
- `768px` 以下将步骤链改为纵向，参数表改为两列并让说明换到下一行。
- 正文不小于 14px；重要说明不小于 16px。
- 不使用依赖 hover 才能读取的信息。

## 自检

- [ ] 主锚点是会影响操作成败的动作或判定。
- [ ] 参数名、单位和示例值与原始材料一致。
- [ ] 示例值与正式配置值已经区分。
- [ ] 可选项、默认值和不可随意修改项已标明。
- [ ] 参数区不是等尺寸卡片堆叠。
- [ ] 成功状态可被用户直接观察。
- [ ] 单文件离线可用，移动端可读。
