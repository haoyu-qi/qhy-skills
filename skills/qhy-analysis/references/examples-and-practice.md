# 示范与表达训练

以下是人为设定的演示材料，不是用户经历或行业事实；只学结构，不把事实移入用户正文。

## 选题拆解示范

输入：“假设团队想用 AI 整理纪要，当前只要求输出文字，还没验证待办准确性。拆一下。”

- **判断**：先验证纪要能否支持执行，再决定扩大使用。
- **标准**：结论忠实、待办可追溯、责任人明确、未知日期不被误填。
- **关键依据**：纪要用于传递决定和任务，文字完整不等于决定和任务准确。这是用途推论，未声称实测收益。
- **比较**：人工整理可处理隐含语境；AI 草稿配人工校验可以试验；自动流转需要验收证据。不能直接排除人工或声称自动流转已可用。
- **动作**：选一份获授权的会议记录，对照草稿结论和任务，列错写、遗漏与无法确认项。缺责任和日期时保留空缺。
- **收束**：先完成对照验收，结果支持后再讨论接入流程。

无需四字定义、反转句或比喻，问题、尺度、比较和动作已清楚。

## 口播示范

> 如果会议纪要要用来安排后续工作，就要检查里面的结论和任务是否准确。AI 可以先给草稿，但这份草稿还没有经过验收。可以拿一份会议记录对照检查，看看有没有漏掉决定、写错责任人，或者把没确定的时间写成了截止日期。先把这些问题查清楚，再决定是否接进日常流程。

可选标注：“如果会议纪要/要用来安排后续工作，//就要检查里面的【结论和任务】/是否准确。↘”

条件不能删，草稿不能被写成已经可靠完成，读法不能扩大承诺。

## 保真清理示范

原稿：“在当今快速发展的时代，AI 赋能会议纪要至关重要。该试点可能减少整理时间，但目前只比较了一次会议。”

清理：“AI 可用于整理会议纪要。该试点可能减少整理时间，但目前只比较了一次会议。”

只改空泛开头和宣传修饰，保留“可能”和样本限制；不能改成“已大幅提高团队效率”或补“我亲测”。若功能本身缺支撑应保留归因或提示核实，不靠润色创造依据。

## 结构诊断示范

假设原顺序：“功能 → 宣称更好 → 用途 → 价格 → 案例”。主要问题是更好无标准，案例也未紧邻判断。

建议：“用途与条件 → 标准 → 按同标准展示功能和案例 → 成本 → 场景选择”。只授权去 AI 味时将其作为建议，正文不搬段。

## 可选十四天训练

仅在用户请求训练时使用，按时间裁剪，不给普通任务强加作业。

| 日程 | 练习 | 验收 |
| --- | --- | --- |
| 1—2 | 复述本人旧稿主问题和结论 | 能说明各段作用 |
| 3 | 最小清理 | 每改可解释，条件无丢失 |
| 4 | 定义领域概念 | 外行可转述，不要求四字 |
| 5 | 比较现有与补充标准 | 说明用途和验证 |
| 6 | 比较现实方案 | 每项有优势和有证据的限制 |
| 7 | 为机制设计类比 | 对应与失效边界清楚 |
| 8—9 | 写整稿 | 问题有答案，案例紧邻依据 |
| 10—11 | 试读、修气口与指代 | 可念，推理关系完整 |
| 12 | 缩成短讲解 | 不扩大结论 |
| 13 | 录制或请读者阅读 | 记录卡点，不虚构反馈 |
| 14 | 按真实反馈复盘 | 能复述判断、依据、范围 |

验收靠真实试读与反馈，未执行不能宣称“语言 DNA 已复刻”或“表达已提升”。
