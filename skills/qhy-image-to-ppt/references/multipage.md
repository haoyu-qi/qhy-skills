# 多页还原与合并

## 输入到页码的映射

先保存 `deck-plan.json` 或同等清单，记录源文件、目标页码、内容区块及操作模式。路径属于本次任务，不写进技能本身。

```json
{
  "mode": "new",
  "canvas": {"width": 1672, "height": 941},
  "slides": [
    {"slide": 1, "source": "image-a.png", "region": "whole", "id": "page-01"},
    {"slide": 2, "source": "image-b.png", "region": "whole", "id": "page-02"}
  ]
}
```

`mode` 可为 new、append、replace；替换场景另记录源 PPTX 和被替换页码。明确指定顺序优先，其次上传顺序，批量文件可采用文件名自然排序（2 在 10 前）。顺序无法确定且影响叙事时再询问，不凭文件修改时间猜测。

相同图片被用户重复上传时先识别重复，不自动删页：用户可能有意重复。按明确请求处理；会影响页数时简短核实。

## 同一本 PPTX 的画布

PowerPoint 演示文稿通常共享一种页面尺寸，不能假设每张幻灯片能有独立比例。

- 已有 PPTX 以它的页面尺寸为准。
- 新文件里所有源图同尺寸/同比例时按原比例建画布，除非用户另有指定。
- 混合比例时优先采用用户指定尺寸；否则采用第一张完整页面图片的比例，声明这一假设。其余页统一等比缩放，居中留边，保持内容完整。不要拉伸图片或默认裁掉边缘内容。
- 元素坐标由同一缩放系数与偏移变换；字体、线宽、圆角和图片同步调整。

## 长图拆页

依标题、主题、模块边界划分，先设计页内内容再重建。保持流程的上下文，必要的跨页衔接用简短原生标记说明。完整图表、架构核心或长表有跨页需求时，优先保持语义整体；必须分割表格时保留表头，不能隐藏行。

用户未限定页数时以可读性决定，不把长图强行压成小字单页。用户要求一张长图只做一页时，遵守并保留其比例或在指定画布内等比适配，说明必要的阅读限制。

## 逐页构建与样式

共享字体映射和相同语义的样式参数，但不把本来不同的主题强行改成一个主题。每页使用 `page-01-...` 等唯一对象/素材标识，防止图标引用串页。真实相同的品牌资产可复用，文字与布局保持页级隔离。

先完成并验证一页代表性密集布局，再将可靠的构建方法应用到其他页；不要把样例页的固定坐标、业务文字或页数复制成通用约束。支持按页重建和局部修订，最后只合并当前通过检查的页。

## 追加/替换已有演示文稿

读取并保留原文件。先确认当前工具的导入再导出能保留原有图表、备注、媒体及对象。如果导入有具体丢失风险，选择能保持原页面结构的合并方式或保留原幻灯片 XML/关系，并做实际验证；不要把所有旧页转为图片以“保真”。

替换只作用于指定页，追加遵守插入位置。未给定替换目标且无法可靠判断时才询问；不要随意覆盖。确认完成后输出新 PPTX，原文件继续保留。

## 验收与交付

逐页从最终文件渲染检查，联系图只检查跨页风格和顺序，不能代替每页细节。检查每个源区块都有去向，禁止通过最终页数正确掩盖漏页或重复页。

`audit_pptx.py --expected-slides N --require-native-text` 检查页数并列出每页对象计数。混有用户要求保持不动的图片页时，不使用“每页必须有原生文字”的门禁，而逐一核对新建/替换页。默认交付一个多页 PPTX；只有用户要求时才另交单页拆分文件。
