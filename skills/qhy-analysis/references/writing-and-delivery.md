# 成稿、口播与交付

成稿前用蓝图锁定主问题、依据和顺序；用户已要求成稿时内部完成，不再请求批准蓝图。

## 按用途写成品

| 形态 | 重点 | 默认交付 |
| --- | --- | --- |
| 文章/技术解读 | 标题准确、段落推进、材料与评论分清 | 标题与正文，引用靠近事实 |
| 业务分析/内部分享 | 结论容易找到，条件、代价与动作清楚 | 正文，必要时附比较表 |
| 认知口播 | 听众知道主题，术语可听懂，依据不漏 | 可直接念的净稿 |
| 个人叙事 | 真实选择、行动、代价与修正 | 用户本人视角的稿子 |
| 教程/作品复盘 | 结果与验证、步骤和失败分支 | 可执行讲稿，必要时含演示提示 |
| 播客/对谈 | 议题地图、主问题、追问与收束 | 主持提纲，不编嘉宾答案 |
| 直播 | 议程、检查点、互动分支与边界 | 流程提纲，不把现场反应预写成事实 |

“分享稿”未指定 PPT 时先交内容。需要 Word、卡片或 PPT 文件时用宿主相应能力完成，不承诺本技能自带排版或发布工具。

## 开头与结尾

可从真实场景、问题、结论、成果或具体争议进入。没有真实场景可直接讲问题或使用明确标清的假设；不虚构网友留言和亲历来做钩子。

标题写对象及信息增量，可用结论或问题，不因上游样本禁用问号或否定标题。吸引力不能超出证据；用户需要选标题时再给多版本。

结尾回答开头，落到“哪些条件下选什么/现在做什么/后续看什么信号”。不强制 12 字金句、升华、自嘲或笑场。

## 句子承载推理

明确因果、条件、让步与所指。复杂句可以分几次呼吸，不能为了短句把推理剁成断言。

以下只示范结构，不代表事实：

- 条件：“如果任务能独立验收，可以先做试点；任务依赖多人协作时，还要确认交接和责任。”
- 理由：“先检查输入材料，因为信息不完整会影响后面的判断。输入稳定后，再比较处理方案。”
- 让步：“这项指标能说明速度，但没有反映返工。评估整段流程时还需算上返工成本。”
- 回指：“这次修改减少了一个人工步骤。接下来要验证，这个步骤省掉后是否增加审核负担。”

不复制这些骨架填满全文。原中文已清楚时不额外加“所以/也就是说/它”；长定语可拆后，专业词和限定不丢。

## 口播执行

净稿保留可读标点。通过实际朗读定位卡嘴、换气与所指不明处。逗号间字数只是线索，不代表真实气口。

用户需要录制或配音时再给标注稿和时长表：

| 标记 | 用途 |
| --- | --- |
| `/` | 短停/换气 |
| `//` | 转折或重点前停顿 |
| `///` | 段间/结论后的留白 |
| `【词】` | 重读 |
| `↗ / ↘ / →` | 提问、收束、平叙 |

这是表演建议，不照搬特定人的秒数、音色和身份。只标关键处；称呼、“对吧”“OK”“我觉得”按作者习惯，不补配额。

优先按用户试读速度估时；无样本时可用约 250—300 汉字/分钟粗估区间，另留演示和停顿。这是工作假设，不是用户实测。上下界分别为字数 ÷ 300、字数 ÷ 250；英文术语、数字读法与演示影响时长。严格时长须试读校准。

| 段落 | 作用 | 字数/估计口播 | 演示与留白 | 验证方法 |
| --- | --- | --- | --- | --- |

短视频裁成一个主要判断、一条依据及一个动作或边界，不把长稿十段硬塞进 90 秒。

## 可用功能块

按需选择定义、标准、对比、实测、成本、思想实验、关键步骤、修正、边界、利益关系、具体感谢与下一步，顺序由论证决定。

- 实测交代条件、步骤、结果；没有亲测材料不写“我测下来”。
- 成本覆盖真实人力、时间、资源和失败代价，不吓唬读者。
- 存在且相关的赞助、收费与利益关系直说，不加防御性嘲讽。
- 事实错误或方案失败先给更正及证据，再说明影响；自嘲不能替代纠错。
- 感谢写真实对象和具体帮助；没提供姓名则用泛称或不写。

录制前核对数字和引语。剪辑保留理解所需的停顿、限定及失败说明；字幕与口播事实一致，避免只截绝对结论误导。
