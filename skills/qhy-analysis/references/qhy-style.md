# QHY 风格与保真

默认风格取自 qhy-humanizer-zh 的保真编辑、qhy-word 的业务写作标准，以及 qhy-card 观点社论模式的主命题与取舍表达。它是可调整的工作默认值；未获得作者样文，不宣称已识别用户完整语言 DNA。

用户本次要求 > 本次相关作者样文 > 本文默认规则。样文有稳定设问、长句、破折号或口语时允许保留。正式分析不硬加“我/你”，个人文章也不强改成公文。

## 默认写法

- 先让读者知道这篇在回答什么。业务分析一般把结论放前面，解释性文章可从真实场景进入。
- 一段发展一个中心，后句解释、限定或推进前句。不能只把摘要摆在一起；并列条目确实用于比较时可以并列。
- 用普通词表达判断，再给材料。名称保持一致，不频繁换同义词制造文采。
- 谈问题时说具体对象、条件和影响；建议说明动作及验证方式，责任人、日期只取自材料或用户要求。
- 主命题要能统领全文。内容有路线、优先级或权衡时呈现它们，不把所有材料压成等权重金句。
- 情绪和立场按材料保留。判断克制不等于削弱作者观点，清楚有力也不等于补“绝对/必然”。

## 信息保真

改写前锁定主体、数值与单位、时间与统计口径、否定、适用条件、归因、因果方向、观点强度、直接引文。

不能把“可能减少返工”改成“解决返工”，把“测试阶段”改成“已上线”，把“据某报告”改成作者确认。比喻中的承诺不能转成事实。引文、代码、URL 和机器字段保持原样；可疑事实单列疑点。

没有的数据、姓名、客户、经历和笑场不能补造。第一人称经历只能来自用户。可用明确标注的假设场景解释机制，但不能用于证明现实收益。

判断缺证据时，说明条件与验证动作，或保持问题开放；不能通过添一条 `[待核实]` 把它包装成确定结论。

## 定位中文编辑问题

出现下列特征时先看上下文，只有造成具体问题才改，不设零命中目标。

| 候选 | 真正要检查的事 | 保留条件 |
| --- | --- | --- |
| “不是……而是/你以为……其实” | 是否凭空制造误解、反复假装反转 | 真实纠错、对照、排除结论保留 |
| 相邻段重复骨架 | 是否重复结论而没有新增材料 | 步骤、条款、作者排比保留 |
| 长定语、多重“的” | 是否找不到中心词 | 固定术语与顺畅长句保留 |
| “对于……来说/当……时” | 删后范围或条件有无改变 | 对象和触发条件有实质作用时保留 |
| “这意味着/问题在于/听起来” | 指代清楚吗，是否只是复述 | 推论、评论或新判断有信息时保留 |
| 破折号、冒号、标题序号 | 是否制造多余揭晓、空转导航 | 解释、停顿、层级、交叉引用保留 |
| 顿号与长列表 | 能否改善句法而保留项目 | 必要项目全保留，不能删项目凑节奏 |
| “全能管家”等人格比喻 | 是否只褒奖、不解释功能 | 有具体对应关系的类比保留 |
| “赋能/闭环/降本增效” | 是否指向具体流程、对象和指标 | 真实术语可定义后使用，不机械换词 |
| 宣传腔、套话开头与万能结尾 | 能否删而不丢信息 | 作者真实评价、正式体裁要求保留 |

“故障不在数据库，而在网关”有排除信息，不能因为反转句式被删；“这不仅是更新，更是时代革命”缺机制和证据时不能再润色成更强判断。

“首先”、三项列举、相近句长、被动句、设问或普通比喻不能单独判为问题。不要为更像人而塞语气词、经历、错别字，或把专业中文强改为聊天语气。

## 范围控制

- **新写/明确重写**：可以重排论证、合并重复段落、改标题，事实边界不变。
- **仅清理/仅去 AI 味**：保留章节、段落顺序和位置；未造成问题的文字保留，只修定位的问题。
- **精简**：可删重复内容，不能删条件、反例、必要数据及用户要求的项目。
- **诊断**：给具体位置、影响和修改示例，不直接覆盖正文。

清理时若根本问题是缺证据或论证断裂，单列提示；不要借“去 AI 味”补论据或换立场。原稿没有值得修改的问题，可以保留。
